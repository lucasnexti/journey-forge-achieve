- Course content hierarchy is tracks → course_modules → lessons (lessons.module_id) + module_materials; lesson_materials is legacy/unused. Why: modules were added additively without breaking existing lessons/progress.
- Course material files live in the private `course-materials` bucket and are opened only via short-lived signed URLs (src/lib/courseMaterials.ts). Why: materials are for signed-in students only.
- Lesson completion and enrollment status are decided by database triggers (enforce_lesson_progress / enforce_enrollment_status, SECURITY INVOKER so trusted RPCs bypass them); the browser only reports watch time. Why: students must not be able to mark videos or courses complete themselves.
- Certificate PDFs are generated only by the generate-certificate backend function, using the built-in official Nexti layout (official.ts, with QR to /validar-certificado/<code>) unless an admin PDF template is linked to that course (private certificates bucket, templates/ and issued/<user_id>/); a certificate row must already exist (created by the exam/no-exam completion RPCs). Why: the browser must never decide certificate data or eligibility.
- Personal data saves use the validated save_my_personal_data RPC; self-reported workplace_empresa is separate from managed empresa affiliation, and profile email does not alter login credentials. Why: editing contact details must not grant access to another company's data or change authentication silently.
- Student and admin sidebar avatars read the shared profile query; avatar saves invalidate profile queries. Why: the saved photo must stay synchronized across navigation.
- Do not mount floating React Query devtools in the app preview. Why: their launcher obscures the sidebar profile photo and user controls.
- Learning paths aggregate existing tracks through ordered associations; canonical companies and admin-validated memberships authorize company grants. Why: preserve course history and prevent self-declared affiliation from granting access.
- Save learning-path content through the transactional save_learning_path RPC; restricted courses stay restricted after removal, and server predicates enforce grants and sequence across content/RPC/storage paths. Why: revocation and direct links must not bypass access checks.
- Learning-path grants use the admin-only set_learning_path_access RPC with serialized, idempotent writes; diagnostics evaluate access server-side without minting learner sessions. Why: stale clients must not break re-grants or expose access checks to learners.

- The "Nexti na Prática" knowledge base is the original static site in public/nexti-na-pratica/, shown in an iframe at /nexti-na-pratica/* (hash route #/x ↔ /nexti-na-pratica/x); inside the app its content comes from public.knowledge_base_content via get_knowledge_base/save_knowledge_base (admin-only publish, drafts hidden from non-admins) through window.parent.__nextiNaPratica, with dados.js as the fallback. Why: keeps its layout isolated while letting admins publish edits for everyone.
- First-access onboarding is shown only while profiles.onboarding_completed is not true and is finished through the complete_onboarding RPC (validates interest-area keys, writes workplace_empresa, never managed empresa). Why: completion must persist across devices and self-declared data must not change company affiliation.
